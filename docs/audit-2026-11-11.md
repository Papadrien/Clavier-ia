## 3. Bugs

### BUG-01 (élevé, à confirmer sur appareil) : Entrée n'exécute pas l'action de l'éditeur
- **Où** : `app/src/main/java/fr/junade/taipo/FieldEditor.kt:127-137` (`pressEnter`).
- **Constat** : quand le champ a une action (`IME_ACTION_SEND`, `SEARCH`, `GO`, `NEXT`, `DONE`), le code appelle
  `sendDownUpKeyEvents(KEYCODE_ENTER)`. Aucun `performEditorAction` n'existe dans le projet. Un `TextView` reçoit alors
  `onEditorAction(IME_NULL)` : les applications qui testent `actionId == IME_ACTION_SEARCH/SEND` ne réagissent pas, et les
  éditeurs non natifs (WebView, Flutter, React Native, Compose multiligne) peuvent insérer un retour à la ligne ou ne rien faire.
  `EditorInfo.actionId` / `actionLabel` (action personnalisée) sont ignorés.
- **Correction** : si `actionLabel != null && actionId != 0` → `ic.performEditorAction(info.actionId)` ; sinon si le champ a une
  action et pas `IME_FLAG_NO_ENTER_ACTION` → `ic.performEditorAction(action)` ; sinon `commitText("\n", 1)`. Garder le repli
  `sendDownUpKeyEvents` si `performEditorAction` renvoie `false`. Sortir la décision dans une fonction pure (`EnterAction.of(imeOptions,
  actionId, hasLabel)`) testée en JVM.
- **Validation** : test JVM de la décision ; sur appareil : recherche Play Store, barre d'adresse Chrome, champ « Suivant » d'un
  formulaire, envoi dans une messagerie, champ multiligne (retour à la ligne conservé).

### BUG-02 (élevé) : une erreur passagère efface des données de l'utilisateur
- **Où** : `dictionary/PersonalDictionaryProvider.kt:41-51`, `clipboard/ClipboardProvider.kt:73-83`,
  `suggestion/NextWordRepository.kt:124-128`, `dictionary/CorrectionHabitsRepository.kt:128-132`.
- **Constat** : `catch (e: Exception)` → suppression de la base ou du fichier + `keyProvider.reset()`. Toute exception déclenche
  l'effacement, y compris une erreur temporaire : Keystore indisponible, disque plein, erreur d'E/S, base verrouillée.
- **Correction** : n'effacer que sur corruption certaine (`AEADBadTagException`, `KeyPermanentlyInvalidatedException`,
  `SQLiteDatabaseCorruptException` / message « file is not a database », format illisible). Pour le reste : journaliser, ne rien
  supprimer, repartir sur un état vide en mémoire **sans écrire par-dessus** et réessayer à la prochaine ouverture. En cas de
  corruption certaine, renommer en `*.corrupt` (un seul exemplaire) au lieu de supprimer. Mettre la classification dans une
  fonction pure testée.
- **Validation** : tests JVM de la classification ; test instrumenté existant (`PersonalDictionaryDatabaseTest`) complété : une
  `IOException` simulée à l'ouverture ne supprime pas la base.

### BUG-03 (moyen) : `writeAtomically` n'est pas durable
- **Où** : `core/src/main/kotlin/fr/junade/taipo/suggestion/AtomicFileWrite.kt:14-21`.
- **Constat** : `temp.writeBytes()` puis `renameTo()` sans `fsync`. Après une coupure, le fichier renommé peut être vide ou
  tronqué ; au démarrage suivant il est illisible et BUG-02 l'efface avec sa clé.
- **Correction** : `FileOutputStream(temp).use { it.write(bytes); it.fd.sync() }` avant le renommage. Même chose pour le modèle
  téléchargé avant `Files.move` (`model/download/ModelInstaller.kt:123-139`, puis 166-169).
- **Validation** : `AtomicFileWriteTest` toujours vert ; relecture.

### BUG-04 (moyen) : fermeture du moteur IA sans verrou
- **Où** : `TaipoIme.kt:677-690` (`onDestroy` appelle `llmHost.close()`), `ai/LlmEngineHost.kt:232-240`.
- **Constat** : `close()` est public, s'exécute sur le fil principal et ne prend pas `inferenceLock`, alors qu'une correction ou
  une génération peut tourner sur `Dispatchers.Default` : risque de plantage natif (moteur utilisé après fermeture) et blocage du
  fil principal pendant la fermeture. `serviceJob.cancel()` n'arrive qu'après.
- **Correction** : dans `onDestroy`, annuler d'abord les tâches (`serviceJob.cancel()`, `correctionEngine.cancel()`,
  `prompt.stopGeneration()`), puis fermer le moteur hors du fil principal sous `inferenceLock` (portée de processus, pas
  `serviceScope`). Rendre `close()` privé ; exposer `closeLocked()` (suspend, prend le verrou).
- **Validation** : relecture ; sur appareil : désactiver le clavier pendant une génération, sans plantage.

### BUG-05 (moyen, à confirmer sur appareil) : cache du champ faux quand l'éditeur refuse ou transforme le texte
- **Où** : `InputTextCache.kt:98-112` (`onCommit`), `CachingInputConnection.kt:41-45`.
- **Constat** : après `commitText`, le cache ajoute le texte tel quel. Si l'éditeur le refuse (longueur maximale, `InputFilter`)
  ou le transforme (majuscules forcées, mise en forme d'un numéro), aucun `onUpdateSelection` ne vient démentir, et le cache
  reste faux jusqu'à 500 ms. L'autocorrection qui suit calcule `deleteSurroundingText` sur un texte qui n'existe pas.
- **Correction** : avant tout `deleteSurroundingText` décidé à partir du cache (autocorrection, mot suggéré, annulation), relire
  le champ réel pour la longueur concernée (lecture directe `wrapped`, sans cache) et abandonner si le texte diffère. Variante
  plus simple : invalider le cache quand l'écho de sélection attendu n'est pas arrivé avant la frappe suivante.
- **Validation** : `InputTextCacheTest` complété (commit refusé, commit transformé) ; sur appareil : champ limité à 5 caractères.

### BUG-06 (faible) : « Effacer les données apprises » peut être annulé par le chargement
- **Où** : `suggestion/NextWordRepository.kt:101-109` (`clear`).
- **Constat** : contrairement à `CorrectionHabitsRepository.clear` (lignes 97-114), il n'attend pas la fin du chargement et ne
  prend pas `writeLock` : un chargement en cours refusionne les anciennes données, une sauvegarde en cours réécrit le fichier.
- **Correction** : même séquence que `CorrectionHabitsRepository.clear` (voir QUAL-01 : une seule classe pour les deux).
- **Validation** : test JVM sur la classe commune.

### BUG-07 (moyen) : décodage final de la dictée sur le fil principal, flux natif non libéré
- **Où** : `ai/VoiceRecorder.kt:199-233` (`stopAndGetResult`), appelé depuis `VoiceController.kt:352-380`.
- **Constat** : `inputFinished()`, `decodeAvailable()` et `currentText()` s'exécutent dans la coroutine appelante (fil principal) :
  saccade à la fin de la dictée. Le flux `OnlineStream` n'est jamais libéré (`release()`), seulement par le ramasse-miettes.
  Le délai de silence utilise `System.currentTimeMillis()` (ligne 172) au lieu d'une horloge monotone.
- **Correction** : `withContext(Dispatchers.Default)` autour du décodage final, `finalStream.release()` dans un `finally`,
  `SystemClock.elapsedRealtime()` pour le silence.
- **Validation** : relecture ; sur appareil : dictée longue, fin sans saccade.

### BUG-08 (faible) : le moteur de dictée peut être libéré pendant un décodage
- **Où** : `ai/VoiceEngine.kt:42-71` (`ensureLoaded` sans verrou), `86-102` (`close`, `releaseEverywhere`).
- **Constat** : `releaseEverywhere()` (suppression du modèle vocal depuis les réglages) libère le moteur natif sans attendre un
  décodage en cours ; deux `ensureLoaded` simultanés chargent deux moteurs.
- **Correction** : un `Mutex` par `VoiceEngine` autour du chargement, du décodage et de la fermeture, comme `LlmEngineHost.inferenceLock`.

### BUG-09 (faible) : restauration ou export interrompu par une rotation
- **Où** : `BackupActivity.kt:40` (`MainScope`), `64-67`, `158-177`.
- **Constat** : la portée est annulée dans `onDestroy` ; une rotation ou un changement de thème pendant la restauration
  l'interrompt à moitié, sans compte rendu.
- **Correction** : exécuter `BackupService.restore/collect` dans une portée d'application et ne garder dans l'activité que
  l'affichage du résultat (ou `ViewModel` + `lifecycleScope`).

### BUG-10 (faible) : texte en cours perdu dans les fenêtres du presse-papiers
- **Où** : `ClipboardEditActivity.kt:63-106`, `144` (champ créé sans identifiant), `ClipboardLabelActivity`.
- **Constat** : `configChanges` couvre la rotation, pas `uiMode` ni `fontScale` : à un changement de thème système l'activité est
  recréée et `show(text)` remet le texte d'origine.
- **Correction** : donner un identifiant au champ et ne pas réécrire le texte si `savedInstanceState != null`.

### BUG-11 (faible, à confirmer sur appareil) : le surlignage de correction peut rester dans le texte
- **Où** : `CorrectionAiController.kt:337`, `547`, `597` (`commitText` d'un `SpannableString` avec `BackgroundColorSpan`).
- **Constat** : dans un éditeur de texte riche, le fond coloré peut devenir une vraie mise en forme si l'utilisateur envoie avant
  que le surlignage soit retiré.
- **Correction** : vérifier sur Gmail, Google Docs, Samsung Notes, Keep. Si le fond persiste : passer par une région de
  composition (`setComposingRegion` + style) ou retirer le surlignage après un délai court.

## 4. Sécurité et vie privée

### SEC-01 (élevé) : les copies sensibles sont écrites dans l'historique
- **Où** : `ClipboardController.kt:165-173` (`reader.start()` dès la création du service), `475-505`,
  `clipboard/ClipHistoryDao.kt:67-88`, `clipboard/ClipboardReader.kt:45-69`, `clipboard/SensitiveContentDetector.kt`.
- **Constat** : le clavier écoute toutes les copies, même masqué, et les enregistre 12 h (7 jours avec le pass). Une copie
  marquée `EXTRA_IS_SENSITIVE` (gestionnaire de mots de passe) est **enregistrée** avec `sensitive = 1`. Avant Android 13 ce
  drapeau n'existe pas : seul un numéro de carte (Luhn) est reconnu, un mot de passe copié finit donc en clair dans le panneau.
  La base est chiffrée, mais la donnée reste lisible par quiconque tient le téléphone déverrouillé. Aucun réglage ne coupe l'historique.
- **Correction** : (1) ne jamais écrire en base une copie marquée sensible (mémoire seulement, pour la puce masquée) ;
  (2) ajouter un réglage « Historique du presse-papiers » (activé par défaut, à confirmer en section 10) ; (3) avant Android 13,
  ne pas enregistrer une copie faite alors que le champ actif est un champ de mot de passe ; (4) purger à la migration les lignes
  `sensitive = 1` existantes.
- **Validation** : `ClipboardDatabaseTest` / tests JVM : une copie sensible n'est pas en base ; le réglage coupe l'enregistrement.

### SEC-02 (élevé) : `TYPE_TEXT_FLAG_NO_SUGGESTIONS` ignoré
- **Où** : `suggestion/SuggestionPolicy.kt:16-38` ; utilisé dans `TaipoIme.kt:485-493`.
- **Constat** : une application qui pose ce drapeau (identifiants, codes, terminaux, champs de code) reçoit quand même
  suggestions, autocorrection et apprentissage du mot suivant.
- **Correction** : `allowsSuggestions`, `allowsLearning`, `allowsEmojiSuggestions` renvoient `false` si le drapeau est posé
  (classe texte). L'autocorrection suit (`autocorrectionAllowed` dépend de `suggestionsAllowed`).
- **Validation** : cas ajoutés au test de `SuggestionPolicy`.

### SEC-03 (moyen) : dictionnaires téléchargés sans empreinte
- **Où** : `dictionary/download/DictionaryDownloadWorker.kt:91-114` (`expectedSha256 = null`, `allowMobileData = true`),
  `dictionary/download/DictionaryContentCheck.kt` (20 premières lignes seulement), `BigramDownloadWorker`.
- **Constat** : l'intégrité repose sur TLS et sur un contrôle de forme. Un fichier modifié sur le serveur change ce que
  l'autocorrection écrit à la place de l'utilisateur.
- **Correction** : manifeste d'empreintes. Soit figé dans l'application (comme `AiModel.sha256`), soit un `manifest.json` versionné
  sur le serveur, signé (Ed25519, clé publique dans l'application) pour garder les mises à jour de listes sans nouvelle version.
  Vérifier le fichier entier avant installation.
- **Validation** : test JVM : empreinte différente → fichier refusé, rien d'installé.

### SEC-04 (faible) : état du pass premium
- **Où** : `PremiumPass.kt:41-59`, `premium/PremiumBilling.kt:86-105`, `res/xml/backup_rules.xml`, `data_extraction_rules.xml`.
- **Constat** : `premium_prefs` n'est pas exclu des sauvegardes (l'état « acheté » suit un transfert d'appareil jusqu'au prochain
  `refresh()`), et aucune signature d'achat n'est vérifiée. Sans serveur, c'est difficile à éviter ; l'enjeu est faible.
- **Correction** : exclure `premium_prefs.xml` des trois sections de règles (et de `BackupRulesTest`) ; `refresh()` reste la source.

### PRIV-01 (élevé) : mesure d'usage envoyée avant information
- **Où** : `MainActivity.kt:75` (`Analytics.firstOpen`), `analytics/AnalyticsPreferences.kt:52` (`DEFAULT_ENABLED = true`).
- **Constat** : `first_open` part dès le premier écran. L'utilisateur ne voit l'interrupteur qu'en bas de l'accueil.
- **Correction** : voir section 10 (choix entre accord explicite et information). Au minimum : carte d'information avec
  l'interrupteur à l'étape d'accueil, et `firstOpen` différé jusqu'à ce que cette carte ait été affichée.

### PRIV-02 (moyen) : textes de confidentialité inexacts
- **Où** : `res/values/strings.xml:476`, `480` ; `res/values-fr/strings.xml:489` et la section 4 correspondante.
- **Constat** : (a) la section 2 dit que la mesure se coupe « dans les paramètres du clavier », alors que l'interrupteur est sur
  l'accueil, section « Mes données » (`res/layout/activity_main.xml:461`) ; (b) la section 4 dit que le presse-papiers est
  désactivé dans les champs de mot de passe, alors que la puce de collage y reste proposée (`SuggestionPolicy.kt:67-71`, voulu) ;
  (c) les journaux techniques envoyés par Google Play Billing, cités dans `README.md:8-9`, ne figurent pas dans le texte de l'application.
- **Correction** : corriger les deux langues ; `PrivacyContentTest` : ajouter une vérification pour Google Play Billing.

### PRIV-03 (faible) : messages d'erreur bruts montrés à l'utilisateur
- **Où** : `ClipboardController.kt:335`, `385`, `403`, `417`, `465` ; `ClipboardEditActivity.kt:215` ; `VoiceController.kt:322`, `373`.
- **Constat** : `t.message ?: t.javaClass.simpleName` est affiché, contre la règle du projet (`docs/securite.md`, « jamais de nom
  de classe ni de message brut »).
- **Correction** : une phrase par cause, détail dans `AppLog` seulement.

## 5. Performances

### PERF-01 (moyen) : chargement du moteur IA en partie sur le fil principal
- **Où** : `ai/LlmEngineHost.kt:86-117`, `119-146`.
- **Constat** : `ensureLoaded` est appelé depuis `serviceScope` (fil principal). Seul `engine.initialize()` passe sur
  `Dispatchers.Default` ; `close()` de l'ancien moteur (ligne 95) et la construction du nouveau s'exécutent sur le fil principal.
- **Correction** : tout le corps après le test « déjà chargé » dans `withContext(Dispatchers.Default)`.

### PERF-02 (faible) : lecture du presse-papiers sur le fil principal
- **Où** : `clipboard/ClipboardReader.kt:45-64`, appelé par `ClipboardController.startListening` à chaque ouverture de champ.
- **Constat** : `primaryClip` est un appel inter-processus qui rapatrie tout le contenu (jusqu'à ~1 Mo).
- **Correction** : lire d'abord `primaryClipDescription` (horodatage) et ne relire le contenu que s'il a changé ; lecture du
  contenu dans une coroutine `Dispatchers.Default` puis publication sur le fil principal.

### PERF-03 (faible) : sauvegarde bloquante dans `onDestroy`
- **Où** : `TaipoIme.kt:677-682`, `NextWordRepository.kt:92-98`, `135-141` (attente jusqu'à 2 s + Keystore + écriture).
- **Correction** : garder l'écriture synchrone mais sans l'attente de 2 s quand rien n'est à écrire (`dirty == false` testé avant
  `loaded.await`).

### PERF-04 (information) : dessin du clavier
`KeyboardView` redessine toutes les touches à chaque toucher (`invalidate()` global). Rien n'est alloué au dessin et les
mesures manquent : ne rien changer sans chiffres. Si les macrobenchmarks montrent des images lentes, mettre les touches au
repos dans un `RenderNode` ou un `Picture` et ne redessiner que la touche pressée.

### PERF-05 (information) : mesures jamais prises
`docs/performance.md` indique que les macrobenchmarks et le profil de démarrage n'ont jamais été exécutés
(`app/src/main/baseline-prof.txt` absent). À faire sur appareil : c'est le gain de démarrage le plus sûr.

## 6. Qualité du code

### QUAL-01 (moyen) : deux dépôts chiffrés quasi identiques
`suggestion/NextWordRepository.kt` et `dictionary/CorrectionHabitsRepository.kt` (~150 lignes chacun) ne diffèrent que par le

BUG-06 au passage et donne un seul endroit pour BUG-02 et BUG-03.

### QUAL-02 (faible) : mêmes blocs répétés

- Les quatre fonctions d'insertion de `TaipoIme.kt:987-1036` finissent par les mêmes cinq appels : extraire `afterFieldEdit()`.

### QUAL-03 (faible) : fils et portées
14 activités héritent de `android.app.Activity` avec `MainScope()` annulé à la main, et des `Thread { }` nus

quand un écran est touché. `GenerationSession.stopScope` (`ai/GenerationSession.kt:70`) n'est jamais annulé.

### QUAL-04 (faible) : état partagé sans garde

### QUAL-05 (faible) : `catch (Exception)` trop large
35 `TooGenericExceptionCaught` et 6 `SwallowedException` dans `quality/detekt-baseline.xml`. À resserrer en priorité dans les
chemins de données (BUG-02).

### QUAL-06 (faible) : dette figée
`quality/ktlint-baseline.xml` : 1 106 écarts, dont 687 `argument-list-wrapping` corrigeables par `./gradlew ktlintFormat` en un
commit dédié, puis régénérer la baseline. `detekt-baseline.xml` : 326 (25 méthodes trop complexes, 18 trop longues, 3 classes
trop grosses). Gros fichiers restants : `KeyboardView` 1 216 lignes, `TaipoIme` 1 162, `Dictionary` 1 121, `CorrectionBarView` 830.

### QUAL-07 (faible) : dépendances
`work` 2.10.0, `customview` 1.1.0, `activity` 1.10.1, `splashscreen` 1.0.1, detekt 1.23.8 (compilateur Kotlin plus ancien que
le 2.4.0 du projet) : vérifier les versions stables actuelles. Aucune vérification des dépendances Gradle

## 7. Interface et parcours

### UX-01 (moyen) : aucun dictionnaire sans réseau
- **Où** : `SuggestionController.kt:537-569`, `dictionary/download/DictionaryDownloadScheduler.kt`, `docs/dictionnaires-distants.md`.
- **Constat** : les listes ne sont plus dans l'APK. Installation hors connexion : clavier sans correction ni suggestions, sans
  message dans le clavier. Une liste modifiée sur le serveur n'est jamais retéléchargée.
- **Correction** : embarquer une liste réduite (français et anglais, ~50 000 mots compressés) utilisée tant que la liste complète
  manque ; afficher une astuce dans la barre quand le dictionnaire de la langue active est absent ; version des listes dans le
  manifeste de SEC-03 pour les mises à jour.

### UX-02 (moyen) : étape « Activer le clavier »
`MainActivity.kt:96-98` ouvre les réglages système ; l'utilisateur doit revenir seul. Surveiller `enabledInputMethodList` tant
que l'écran des réglages est ouvert et ramener `MainActivity` au premier plan dès que Taipo est activé, puis ouvrir le sélecteur.

### UX-03 (moyen) : permission du micro refusée définitivement
`VoicePermissionActivity.kt:22-34` : aucune explication avant la demande, et après un refus définitif la demande ne s'affiche
plus : l'utilisateur voit seulement « permission refusée ». Détecter ce cas (`shouldShowRequestPermissionRationale` faux après
refus) et proposer d'ouvrir la fiche de l'application dans les réglages.

### UX-04 (moyen) : captures d'écran et accès partiel aux photos
`clipboard/ScreenshotFinder.kt:29`, `156-164` : sur Android 14+, si l'utilisateur choisit « Sélectionner des photos »,
`READ_MEDIA_IMAGES` n'est pas accordée et la fonction ne trouve rien, sans le dire. Gérer `READ_MEDIA_VISUAL_USER_SELECTED`
(l'expliquer dans le réglage) ou remplacer par le sélecteur de photos : voir aussi le risque Play noté dans
`docs/play-console-declarations.md`. La copie partagée n'est purgée qu'au partage suivant (`ScreenshotFinder.kt:140-143`) : purger
aussi à la fermeture du clavier.

### UX-05 (faible) : fin d'un téléchargement
`model/download/DownloadNotification.kt` : la notification disparaît à la fin ou à l'échec. Publier une notification finale
(« Modèle prêt » / « Échec, toucher pour réessayer »).

### UX-06 (faible) : la sauvegarde oublie des réglages
`backup/BackupService.kt:58-71` ne couvre pas : langues et dispositions (`keyboard_language`, `multilingual_*`,
`letter_arrangement_*`), police, fond (`keyboard_backdrop*`), sons et volume, marge basse, zones de frappe adaptatives, mode une
main et flottant. Les ajouter (champs facultatifs, `formatVersion` inchangé) ; valider les emojis récents restaurés
(`BackupService.kt:135`). Le nom du fichier « taipo-sauvegarde- » est en français quelle que soit la langue (`BackupActivity.kt:81`).

### UX-07 (faible) : langues de l'interface
Les écrans existent en anglais et en français (681 textes, parité vérifiée), alors que le clavier gère aussi l'allemand,
l'espagnol, l'italien, le portugais et le néerlandais.

### UX-08 (faible) : textes
- `res/values-fr/strings.xml:495` : « Les désinstaller supprime ces données » → « Désinstaller l'application supprime ces données ».
- `MainActivity.kt:105` : le sous-titre de la ligne « Langues » reçoit d'abord le titre (remplacé ensuite dans `onResume`) : passer
  un texte vide ou dédié.

### UX-09 (information) : thème des écrans
Les écrans de l'application sont toujours sombres (`res/values/themes.xml`), seul le clavier suit le thème clair. Voir section 10.

### UX-10 (faible, à confirmer sur appareil) : touche Entrée
`KeyRenderer.kt:443-446` dessine la même icône quelle que soit l'action du champ. Afficher loupe, flèche d'envoi ou « suivant »
selon `imeOptions` (à faire avec BUG-01).

## 8. Accessibilité

Déjà en place : arbre virtuel TalkBack pour les touches et les emojis, zones tactiles étendues à 48 dp, contrastes testés,
plafond de taille de police, titres de section, aucune image sans description dans les mises en page.

- **A11Y-01 (moyen)** : jamais essayé avec TalkBack ni à 200 % de police (`docs/accessibilite.md`). À faire avant publication.
- **A11Y-02 (moyen, à confirmer avec TalkBack)** : le bandeau de message du clavier (`MessagePopup.kt:49`, `60-61`, une
  `PopupWindow` qui disparaît seule en 2,5 à 6 s) n'a pas de région vivante, contrairement à `GestureTipPillView.kt:60` : un
  utilisateur de TalkBack peut ne jamais entendre « correction annulée », « presse-papiers plein », etc. Poser
  `accessibilityLiveRegion = POLITE` sur son texte et allonger la durée quand TalkBack est actif. Les suggestions, elles, ont déjà
  leur description (`SuggestionStripView.kt:191-194`).
- **A11Y-03 (faible)** : `res/layout/view_system_prompt_section.xml`, champ `edit_system_prompt` sans `hint` ni `labelFor`.
- **A11Y-04 (faible)** : touches à 36 dp en paysage, onglets emoji à ~25 dp (relevés dans `docs/accessibilite.md`, non corrigés).
- **A11Y-05 (faible)** : 24 `Toast` dans les écrans : préférer un message dans la page (lisible plus longtemps, relu par TalkBack).
- **A11Y-06 (information)** : RTL déclaré (`supportsRtl`), aucun attribut gauche/droite dans les mises en page, mais les vues
  dessinées au Canvas ne sont pas vérifiées en RTL ; sans objet tant qu'aucune langue RTL n'est proposée.

## 10. Décisions à prendre par Adrien (ne pas trancher seul)

1. **Mesure d'usage (PRIV-01)** : accord explicite à l'accueil (désactivée par défaut) ou information visible avec interrupteur
   (activée par défaut) ? Recommandation : accord explicite, plus sûr pour un clavier diffusé en Europe.
2. **Historique du presse-papiers (SEC-01)** : réglage activé ou désactivé par défaut ? Recommandation : activé, mais les copies
   sensibles ne sont jamais enregistrées.
3. **Dictionnaire embarqué (UX-01)** : accepter ~2 à 3 Mo de plus dans l'APK pour un clavier utilisable hors connexion ?
   Recommandation : oui, pour le français et l'anglais.
4. **Captures d'écran (UX-04)** : garder `READ_MEDIA_IMAGES` (risque de refus par Google Play) ou passer au sélecteur de photos ?
   Recommandation : sélecteur de photos.
5. **Thème clair des écrans (UX-09)** et **traduction de l'interface (UX-07)** : à planifier ou non.
6. **Empreintes des dictionnaires (SEC-03)** : figées dans l'application (simple, une version par mise à jour de liste) ou manifeste
   signé sur le serveur. Recommandation : manifeste signé.
